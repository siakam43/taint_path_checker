# taint-tree-checker 修复与优化设计（基于手工修改的评估）

## 背景与动机

taint-tree-checker 上线后，实际分析中发现两个问题：

1. **逐链分析粗糙**：整树分析时模型注意力分散，每条链的分析深度远低于 taint-path-checker 的单链分析。
2. **错误链不修复**：输入的调用树本身可能不完整（缺分支、链被间接调用截断），skill 按错误的树分析，产生漏报。

用户据此手工修改了 `taint-tree-checker/SKILL.md`（工作区未提交），方向为：树级数据流构建 + 调用树修复。本文档评估该手工修改，并设计进一步优化方案。

## 手工修改评估结论

**方向正确的部分**：

- 新增 4.3"污点传播数据流构建"，引入调用树修复（补充缺失链、补全中断链）——直接针对"错误链不修复"。
- 术语从"链外"改为"调用树外"——语义更准确。

**问题清单**（评估发现 6 类问题，均已纳入本设计）：

| # | 问题 | 严重度 | 处理 |
|---|------|--------|------|
| 1 | 跨链全局污点语义未定义完整：4.1 删除"链间不传播"规则后，4.2(3) 仍残留"链内"措辞；跨链传播隐含的"多次调用"触发前提全文未定义 | 高 | 4.1/4.2 重写为"全树共享+跨调用前提"（见决策 1） |
| 2 | "跳函数"与"跳链"矛盾：三.3 说跳过该函数继续，9.2 说跳过该链 | 高 | 统一为按污点接触性判定（见逐章设计三） |
| 3 | 树修复缺边界与落盘定义：无扩展边界、无间接调用解析规则、修复结果不落盘；7.3 要求摘要写修复情况但 7.4 无对应位置 | 高 | 4.3 重写（见决策 2、3） |
| 4 | 模板与检查清单脱节：7.4 删除"分析情况"小节，但 8.2 仍要求每条链有结论 | 中 | 7.4 恢复"分析情况"，8.2 措辞改为"覆盖结论" |
| 5 | 术语不一致：7.5 标题"链外漏洞标记"与正文"调用树外"混用 | 中 | 标题改"树外漏洞标记"，字段名"是否链外"不动（下游 cleaner 解析依赖） |
| 6 | 硬规则强调句删除（TreeID"不得忽略校验"、报告路径"不得写到其他位置"、对应思维陷阱） | 低 | **维持用户修改，不恢复**。用户决策：外层脚本负责校验，skill 仅在输入解析处说明清楚一次即可，不重复强调 |

## 已确认决策

### 决策 1：全局污点全树共享 + 跨调用前提

- **规则**：污点写入全局/静态变量后，调用树内任何后续函数（含其他链中的函数）读取时视为污点。堆、共享内存（shm、dma_buf）等持久存储同规则。
- **同链内**：写入与读取在同一链中，单次调用即可触发，攻击路径无需额外说明。
- **跨链**：写入在链 A 尾部、读取在链 B，攻击路径必须写明**多次调用**触发序列（如"第一次调用沿链1设置 g_var，第二次调用沿链2触发"）。
- **失效条件**：入口函数或其每次调用的必经路径重置/初始化该全局时，不可跨调用传播。
- **配套**：4.2(3) 表删除"链内"残留措辞；9.1 改写原"链间不传播"陷阱为"跨链读取全局必须写明多次调用前提，入口重置则不可传播"。

### 决策 2：调用树修复规范

- **仅污点驱动**：只记录污点数据实际传播到的调用关系。函数 a 调用 b 但未将污点传给 b 时，a→b 不补入树——防止路径爆炸。
- **两类修复**：
  - 调用链缺失：污点传播到树外函数并继续形成新分支 → 从入口函数起补写完整新链。
  - 调用链提前中断：污点传播到链尾后仍在继续传播（间接调用等原因）→ 延伸该链直至污点停止传播或到达危险使用点。
- **间接调用解析**：通过函数指针赋值、回调注册点在 project_dir 中搜索确定目标函数；无法确定时该分支标注"无法追踪"并停止延伸，不臆造。
- **落盘**：修复后的树写入 `{project_dir}/.ethunter_out/taint-tree-checker/{TreeID}_tree_fixed.json`，格式与输入 JSON 一致（顶层键 `{入口函数名}${TreeID}`，值为链数组，元素 {func, file, begin_line}）。**不修改输入文件**。
- **报告联动**：7.3/7.4 报告均包含"调用树修复情况"（补充/延伸了哪些链，或"未修复"）。

### 决策 3：分析流程四阶段（sink 优先，遍历方式不强制）

取代"逐链完整分析"的隐式要求，把第四、五、六章重组为四阶段：

| 阶段 | 内容 | 对应章节 |
|------|------|----------|
| ① 数据流构建 | 从入口函数出发，沿调用树追踪全部污点传播，**过程中修复调用树**，产出完整准确的污点数据流路线集合。遍历方式不做强制（逐链/广度优先均可），但必须覆盖污点可达的全部代码 | 4.3 |
| ② 危险使用扫描 | 在数据流覆盖范围内寻找所有危险使用点（sink） | 5.1 |
| ③ 校验检查 | 对每个 sink 回溯数据流，检查到达前是否存在校验（显式+隐式） | 5.2 |
| ④ 可达性确认 | **仅在发现候选漏洞后**执行门禁三问；"可触发"须写出完整攻击路径，跨链全局污点触发的漏洞须写明多次调用序列 | 六 |

### 决策 4：反偷懒约束

针对"AI 经常偷懒"：阶段①结尾强制自检——每个污点变量必须追踪到以下终止状态之一：停止传播/被无害消费/被净化/到达危险使用点/标注"无法追踪"（记录于摘要），数据流不完整不得进入阶段②。保留 9.1"分析太长了，后面简化一下"思维陷阱。

## SKILL.md 逐章修改设计

**一、角色与任务概述**：维持用户修改（树级追踪措辞）；漏洞挖掘范围维持"调用树中的函数为主体，树外辅助函数漏洞标注树外"。

**二、输入解析**：维持用户修改，规则在 2.2 一次性说明清楚，不重复强调（外层脚本负责校验）。2.3 新增一句：修复后的调用树写入 `{TreeID}_tree_fixed.json`（与结果文件同目录）。

**三、获取目标代码**：
- 源码缺失规则重写（解决矛盾）：缺失函数**可能接收污点**（参数污点或读取已污染全局；**无法确认时按可能接收处理**）→ 该链污点状态未知，跳过该链、其余链照常，摘要注明"函数 xxx 源码未找到，跳过该链"；**可确认不接触污点**（实参均非污点、无污点全局读取）→ 继续该链分析，摘要注明"函数 xxx 源码未找到，其不接触污点数据，分析继续"。
- 树外函数定位：当污点传递到树外函数时，在 project_dir 中搜索其定义并分析，按 4.3 决定是否补入树。

**四、污点数据追踪**：
- 4.1：入口函数参数污点标记规则不变（首段维持用户修改）；新增"全局污点全树共享"规则段（决策 1 全文）。
- 4.2(3)：全局/静态变量三行改为树级语义——"污点写入全局变量，调用树内后续函数读取 g_var 时视为污点"；静态局部变量同；读取行删除"链内"措辞。
- 4.3：重写为阶段①规范——数据流构建目标（准确完整、覆盖污点可达全部代码）、遍历方式不强制、两类树修复（决策 2）、仅污点驱动边界、间接调用解析、落盘规则、完整性自检（五类终止状态，决策 4）。
- 4.4：与 4.3 联动——树外函数追踪时，污点继续传播到新的树外函数按"调用链缺失/中断"修复；污点在该函数内停止（消费/净化）则不补入树。其余注意事项（同名变量、别名、状态跟踪）不变。

**五、危险使用点与校验检查**：章首衔接句维持用户修改（"在之前输出的污点传播数据流路线中寻找危险使用点"）。5.1/5.2 清单内容不变。

**六、漏洞判定门禁**：三问不变。"可触发"补充：跨链全局污点触发的漏洞，攻击路径须描述多次调用序列（决策 1）。

**七、报告输出**：
- 7.3 无漏洞模板：摘要包含调用树功能、**调用树修复情况**、污点追踪结果、关键校验点、各链覆盖结论（已纳入数据流/跳过及原因）。
- 7.4 有漏洞模板：漏洞列表前恢复"## 分析情况"小节（树内链数、各链覆盖结论、调用树修复情况）。
- 7.5：标题改"树外漏洞标记"；字段名"是否链外"**保持不变**（下游 cleaner 依赖解析），字段值措辞统一为"调用树外"。

**八、执行检查清单**：第 2 项改为"调用树内每条链是否有覆盖结论（已纳入数据流/跳过及原因）"；新增"有树修复时 `{TreeID}_tree_fixed.json` 是否写出"。

**九、自检提醒**：
- 9.1 思维陷阱：改写跨链全局陷阱（决策 1）；保留"链 A 校验结论不得套用链 B"、"树内同 ID 合并攻击路径须可达"、"分析太长"；不恢复 TreeID 校验陷阱（决策：外层脚本校验）。
- 9.2 边缘情况：源码缺失、污点无法追踪两行统一为三.3 的新规则；新增"间接调用无法确定目标 → 该分支标注无法追踪，停止延伸"。

## 与下游兼容性

- 漏洞列表字段名（含"是否链外"）、攻击路径格式、漏洞 ID 生成规则全部不变——taint-path-cleaner 零改动可解析。
- 新增 `{TreeID}_tree_fixed.json` 不影响下游（cleaner 只消费 `_result.md`）。

## 测试验证计划

1. **夹具 tree_test（复用，验证决策 1）**：现有夹具中 FUNC1 写 `g_flag = idx`（链1），FUNC3 读 `g_buf[g_flag]` 且仅校验 `idx` 未校验 `g_flag`（链2）。旧语义只报 1 个漏洞（FUNC2）；新语义期望报 **2 个漏洞**：FUNC2 idx 越界（单次调用）+ FUNC3 g_flag 越界（跨调用触发：第一次调用 cmd=0 设置 g_flag，第二次调用 cmd=1 在 FUNC3 触发）。攻击路径须含两次调用序列。测试前需清理夹具 `.ethunter_out` 旧结果（预查重会跳过）。
2. **夹具 tree_repair（新增，验证决策 2/3）**：构造输入树缺分支（入口调用链外函数且污点继续传播）与链中断（链尾函数经函数指针间接调用）的用例，验证：补链/延伸、`tree_fixed.json` 落盘且格式与输入一致、报告含修复情况、非污点调用关系不补入树。
3. **回归**：taint-path-checker、taint-path-cleaner 的 SKILL.md 不修改；下游 cleaner 用现有夹具报告格式验证解析不受影响。

## 不改动内容

- taint-path-checker、taint-path-cleaner 的 SKILL.md 均不修改。
- 漏洞 ID 生成规则、漏洞列表字段、攻击路径格式不变。
- 排除清单、核心原则（宁可漏报，不要误报）不变。
- 输入 JSON 解析规则（TreeID 以文件名为准等）内容不变，仅保留 2.2 的一次性说明。
