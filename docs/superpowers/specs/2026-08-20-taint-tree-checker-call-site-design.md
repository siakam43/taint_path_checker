## 背景与问题

实测中发现一个漏报场景：函数 a 调用了 2 次函数 b。调用树构造正确（树中只有一条 a→b 边），但第五章"危险使用点与校验检查"只分析了第一次调用：第一次调用的实参已校验，第二次调用的实参未校验，两次调用进入同一函数、到达同一危险使用点，最终因只按"函数"套用校验结论而漏报。

根因：调用树中的一条边只表示"存在调用关系"，不代表"只调用一次"。**形参的污点状态与校验结论应按"调用点"区分，而非按"函数"统一套用。**

此外，第五章现有子标题（5.1 危险使用模式清单、5.2 校验识别清单、5.3 校验完备性检查、5.4 排除清单）是并列的单项规则说明，缺少流程主线，读者难以把握分析顺序与产出关系。

## 目标

1. 将第五章重构为一条完整分析流程：**分析范围确定 → 危险使用点定位 → 校验存在性检查 → 校验完备性检查 → 漏洞分析**，章末衔接第六章"漏洞判定门禁"。
2. 在流程第一步"分析范围确定"中引入**调用点区分原则**：污点绑定与校验结论按调用点区分，任一调用点未正确校验即构成触发路径，解决上述漏报。

### 各小节正文

**第五章引言**（改写）：

> 本章以第四步输出的污点传播数据流路线为输入，按以下流程挖掘因外部污点数据未正确校验导致的安全漏洞：**分析范围确定 → 危险使用点定位 → 校验存在性检查 → 校验完备性检查 → 漏洞分析**。漏洞分析产出的候选漏洞，须通过第六章"漏洞判定门禁"方可上报。

**5.1 分析范围确定**（新增）：

> 以第四步的污点传播数据流路线为基础，确定本章的分析对象。**分析单元是"调用点"，不是"函数"。**
>
> 调用树中的一条边（如 a→b）只表示"存在调用关系"，**不代表"只调用一次"**。调用方可能多次调用同一函数，各调用点的实参不同、校验情况也不同。
>
> - **逐调用点枚举**：回到调用方源码，枚举对同一函数（以及函数内对下游函数）的**全部调用点**，逐一纳入分析范围。不得因"树中只有一条边"只分析一次。
> - **逐调用点绑定实参**：每个调用点独立完成实参→形参绑定。形参的污点状态按调用点区分：同一函数在某次调用中形参为污点、另一次调用中已校验，两种状态并存、分别追踪。
> - **逐调用点成对分析**：同一条数据流经不同调用点到达同一使用点时，每个"调用点→使用点"组合都是独立分析对象。

**5.2 危险使用点定位**：原 5.1 危险使用模式清单整体移入，仅改标题，正文不动。

**5.3 校验存在性检查**：原 5.2 校验识别清单整体移入，改标题，并在开头补一句衔接流程：

> 对 5.2 定位到的每个危险使用点，逐一检查其每个调用点（见 5.1）的实参在到达使用点前是否存在任何形式的校验。

**5.4 校验完备性检查**：原 5.3 整体移入，仅改标题，正文不动。

**5.5 漏洞分析**（新增）：

> 汇总 5.2~5.4 的结果，形成候选漏洞并完成影响分析。

**5.5.1 无校验或校验不完备的危险使用定位**（新增说明）：

> 对每个"调用点→使用点"组合：无校验，或校验不完备（按 5.4 判定，须给出具体绕过路径）→ 记为候选漏洞。
>
> **任一调用点未正确校验即构成触发路径。一个调用点前的校验只覆盖该调用点——"第一次调用已校验"不代表"第二次调用已校验"。**
>
> 候选漏洞的攻击路径必须落在未正确校验的调用点上，并标注该调用点的行号。

**5.5.2 漏洞影响分析与类型排除**：原 5.4 排除清单整体移入，改标题，并在表格前补一句：

> 对候选漏洞分析安全影响（内存破坏、权限提升、信息泄露、代码执行），并按下表排除不关注的问题类型。

**章末衔接句**（新增，置于 5.5.2 之后、第六章之前）：

> 通过 5.5 的候选漏洞，上报前必须逐一通过第六章"漏洞判定门禁"三问，任一条件存疑则不上报。

### test.c（1 入口 2 条链）

```c
#include <stdint.h>

#define BUF_SIZE 64

static uint8_t g_buf[BUF_SIZE];

void FUNC0(uint32_t idx, uint32_t off)
{
    if (idx >= BUF_SIZE)      /* 校验 idx：只覆盖调用点1 */
        return;
    FUNC1(idx);               /* 调用点1：实参已校验 */
    FUNC1(off);               /* 调用点2：实参未校验 → 漏洞经此触发 */
}

void FUNC1(uint32_t v)
{
    g_buf[v] = 0xAA;          /* 危险使用点 */
}

void FUNC2(uint32_t idx, uint32_t off)  /* 对照链：两个调用点均已校验 */
{
    if (idx >= BUF_SIZE)
        return;
    if (off >= BUF_SIZE)
        return;
    FUNC1(idx);
    FUNC1(off);
}
```

### 预期报告要点

- **1 个漏洞**：OOB Write，关键行为 FUNC1 内 `g_buf[v] = 0xAA;`，漏洞 ID 按 `file:func:line`（test.c:FUNC1:关键行号）计算。
- 调用点1与调用点2到达同一危险行、生成同一漏洞 ID，按 7.1 树内去重**合并报告一次**，攻击路径必须落在**调用点2（`FUNC1(off)` 所在行）**，并说明"调用点1已校验、调用点2未校验"。
- FUNC2 对照链两个调用点均已校验，不报漏洞——验证调用点区分不会导致误报。
- 预期报告 `multi01_result.md` 按 7.4 模板撰写，漏洞 ID 实际计算后填入。
