# taint-tree-checker 设计

## 概述

新建 skill `taint-tree-checker`：在 `taint_path_checker` 根目录下创建 `taint-tree-checker/` 文件夹，内含单个 SKILL.md。功能与 `taint-path-checker` 相似，唯一区别是输入从单条调用链变为调用树——以同一入口函数为起点的多条调用链。下游应用仍为 `taint-path-cleaner`（零改动），输出报告格式保持与 taint-path-checker 一致。

## 背景

taint-path-checker 每次分析一条调用链（`callchainID` + `chain` 数组），产出 `{callchainID}_result.md`。当需要分析同一入口函数的多条备选路径时，需要逐链多次调用。taint-tree-checker 将多条链合并为一次树分析任务，共享入口函数只读一次源码，树级报告合并所有链的漏洞。

## 输入数据格式

输入文件命名约定 `{TreeID}.json`，JSON 结构：

```json
{
    "FUNC0$ef4ebf80": [
        [
            {"func": "FUNC0", "file": "/src/a.c", "begin_line": "31"},
            {"func": "FUNC1", "file": "/src/a.c", "begin_line": "156"},
            {"func": "FUNC2", "file": "/src/a.c", "begin_line": "185"}
        ],
        [
            {"func": "FUNC0", "file": "/src/a.c", "begin_line": "31"},
            {"func": "FUNC3", "file": "/src/a.c", "begin_line": "156"}
        ]
    ]
}
```

- 顶层键格式 `{入口函数名}${TreeID}`。
- 值为链数组（非空），每条链为元素数组，元素结构（func/file/begin_line）与原调用链元素一致。
- 入口函数在每条链首位重复出现，与键中入口函数名一致。
- 单链树（数组长度为 1）允许，退化为单链分析。

**TreeID 解析规则**：以文件名为准——TreeID = tree_file 文件名（不含扩展名），与键中 `$` 后部分不一致时在报告中报错并结束本次任务。

## 关键决策

| 决策点 | 结论 |
|--------|------|
| 输出文件粒度 | 每树一个结果文件 `{TreeID}_result.md`，合并所有链的分析 |
| 漏洞所属链标注 | 不标注，攻击路径已详细记录触发过程 |
| 跨链污点状态 | 链间独立，全局/静态变量污点不跨链传播 |
| 部分链失败 | 跳过该链继续其余链，摘要中注明 |
| TreeID 来源 | 以文件名为准，与 JSON 键校验 |
| 实现方式 | 复制 taint-path-checker 为模板改写，逐链独立分析，树级合并报告 |

## 输入变动对原有流程的影响分析

原输入为单链（`callchainID` + `chain`），新输入为树（键 `FUNC0$TreeID` + 链数组）。对原九章流程逐章影响：

**二、输入解析**
- 2.1 命令格式：任务标识从 callchainID → TreeID；文件命名 `{TreeID}.json`。
- 2.2 JSON 格式：结构完全变化。新增解析规则：TreeID 以文件名为准并与键校验；值为非空链数组；每条链首元素 func 与键中入口函数名一致；单链树允许。链元素结构不变。
- 2.3 输出目录：`.ethunter_out/taint-tree-checker/`（目录名随 skill 变化）。
- 2.4 预查重：粒度变为整棵树——`{TreeID}_result.md` 存在则跳过整棵树。
- 2.5 macro.json：不变。

**三、获取目标代码**
- 由遍历单条 chain 变为遍历所有链；同一函数在多链中出现时按 file+begin_line 去重，源码只读一次。
- 源码缺失：由"跳过该函数"变为"跳过该链，继续其余链，摘要中注明"。

**四、污点数据追踪**
- 由单链线性追踪变为逐链独立追踪。全局/静态变量污点仅链内生效，每条链从干净的全局污点状态开始。
- 4.1 初始污点标记、4.2 传播模式清单、4.3 注意事项：内容全部复用，作用域措辞从"调用链"改为"当前分析的链"。

**五、危险使用点与校验检查**：内容不变，逐链执行。

**六、漏洞判定门禁**：三问不变。可触发性描述完整触发路径（自入口参数到漏洞点），该路径即攻击路径。

**七、报告输出**
- 7.1 漏洞ID：生成规则不变（file:func:line 哈希）。新增树内去重：多条链发现相同 ID 的漏洞时合并报告一次，攻击路径记录任一条真实可达的链——避免下游 cleaner 对同 ID 重复分析。
- 7.2 输出文件：`{TreeID}_result.md`。
- 7.3/7.4 模板：头部"调用链ID"→"调用树ID"；无漏洞摘要分链简述；有漏洞报告在漏洞列表前增加"分析情况"小节（树内链数、各链已分析/已跳过）。漏洞列表字段、攻击路径格式不变（下游 cleaner 解析依赖）。
- 7.5 链外漏洞标记：不变。

**八、执行检查清单**：路径与 ID 更新为树版本；新增"每条链均有结论（已分析或已跳过）"检查项。

**九、自检提醒**：新增树特有陷阱（见下文逐章设计）。

## taint-tree-checker/SKILL.md 逐章设计

沿用原 skill 九章框架，改动集中在二、三、四、七、八、九章。

**Frontmatter**：`name: taint-tree-checker`；description 说明输入为调用树（同一入口函数出发的多条调用链），触发命令 `/taint-tree-checker`，适用领域同原 skill。

**一、角色与任务概述**：仅"读取一条函数调用链"→"读取一棵函数调用树"。分析范围、漏洞挖掘范围（链外漏洞标注规则）、业务领域、核心原则（宁可漏报，不要误报）不变。

**二、输入解析**
- 2.1 命令格式：`/taint-tree-checker <project_dir> <tree_file>`；project_dir 可选，默认当前工作目录；tree_file 命名约定 `{TreeID}.json`。
- 2.2 调用树 JSON 格式：完整写入上文"输入数据格式"规范及解析规则（TreeID 校验、非空链数组、入口函数一致性、单链树允许）。
- 2.3 初始化输出目录：`{project_dir}/.ethunter_out/taint-tree-checker/`。
- 2.4 预查重：检查 `{TreeID}_result.md` 是否存在，存在则输出"该调用树已有分析结果：…，跳过分析。"并结束。
- 2.5 加载编译宏配置：原样保留。

**三、获取目标代码**
- 遍历全部链，按 file+begin_line 去重读取函数源码（同函数多链出现只读一次）。
- 某链中函数源码不存在→跳过该链继续其余链，摘要中注明；不中断整树。
- 链外辅助函数追踪规则不变。

**四、污点数据追踪**
- 逐链独立执行：每条链依次走 4.1 初始污点标记（该链入口函数参数）、4.2 传播模式清单（内容原样复用）、4.3 注意事项（"链内"均指当前分析的链）。
- 新增明确规则：**全局/静态变量污点在链间不传播**，每条链从干净的全局污点状态开始分析。

**五、危险使用点与校验检查**：内容原样，逐链执行。

**六、漏洞判定门禁**：三问原样；"可触发"要求描述完整触发路径（自入口参数到漏洞点），该路径即攻击路径。

**七、报告输出**
- 7.1 漏洞ID：生成规则不变；新增树内去重（同 ID 合并报告一次，攻击路径记录任一真实可达链）。
- 7.2 输出文件：`{TreeID}_result.md`，必须生成。
- 7.3 无漏洞模板：头部"调用树ID"；分析摘要分链简述（各链功能、污点结果、关键校验；被跳过链注明原因）。
- 7.4 有漏洞模板：头部"调用树ID"；漏洞列表前增加"分析情况"小节（树内链数、各链已分析/已跳过）；漏洞列表字段表与攻击路径格式原样不变。
- 7.5 链外漏洞标记：原样。

**八、执行检查清单**：输出路径与 ID 更新为树版本；新增"每条链均有结论（已分析或已跳过）"检查项。

**九、自检提醒**
- 思维陷阱新增：
  1. "各链共享入口函数，不得把链 A 的校验结论套用到链 B"；
  2. "树内同 ID 漏洞合并时，记录的攻击路径必须确实可达"。
- 边缘情况表更新：
  - JSON 格式异常（键格式错误 / TreeID 不一致 / 入口函数不一致 / 空链数组）→ 在报告中报错并结束本次任务，不做分析；
  - 某链源码缺失或污点无法追踪 → 跳过该链，其余链照常，摘要注明；
  - 结果文件已存在 → 跳过整树。

## 测试验证计划

skill 为纯 markdown 文档，验证方式为构造测试夹具手动试跑：

1. **新增测试夹具** `test_fixtures/tree_test/`：
   - 源文件构造一棵两链树（对应需求示例）：链1 `FUNC0-FUNC1-FUNC2` 含一个未校验漏洞；链2 `FUNC0-FUNC3` 已正确校验——验证"链间独立"（链2 不应报漏洞）与树级报告正确性。
   - 输入 `ef4ebf80.json`：键 `FUNC0$ef4ebf80`，值为两条链。
2. **试跑清单**：
   - 正常树：产出 `{TreeID}_result.md`，漏洞字段、攻击路径格式与下游 cleaner 要求一致。
   - 预查重：同 TreeID 二次运行输出跳过提示。
   - 异常分支：TreeID 与文件名不一致 → 报错；某链源码缺失 → 跳过该链继续其余链。
   - 下游兼容：用现有 taint-path-cleaner 消费树报告，确认零改动可解析。
3. **回归确认**：taint-path-checker / taint-path-cleaner 为独立文件夹，本次不修改，无回归风险。

## 不改动的内容

- taint-path-checker 与 taint-path-cleaner 的 SKILL.md 均不修改。
- 下游 taint-path-cleaner 的命令格式、输入解析、输出目录、判定逻辑全部不变。
- 漏洞 ID 生成规则（file:func:line 哈希）不变。
- 报告漏洞列表字段与攻击路径格式不变。
- macro.json 加载与宏判定规则不变。
- 排除清单、核心原则不变。
