# taint-path-checker / taint-path-cleaner 编译宏支持设计

## 概述

为两个 skill 新增编译时宏定义的感知能力。通过读取 `.ethunter_out/macro.json` 中的编译指令宏配置，在漏洞判定和误报分析时综合考虑预处理宏条件，避免将编译产物中不存在的代码路径报告为漏洞。

## 背景

当前两个 skill 在分析代码时只能看到源码中的 `#ifdef`/`#ifndef`/`#if` 等预处理指令，但无法感知编译指令（如 `-DABC=0`）中动态定义的宏。当编译宏禁用某段代码时，该代码在最终产物中不存在，不应作为漏洞报告。

## macro.json 格式

文件路径：`{project_dir}/.ethunter_out/macro.json`

```json
{
    "MACRO_NAME": "value",
    "FEATURE_X": null
}
```

- key 为宏名，value 为宏值（字符串）。
- `null` 表示宏仅被定义但无值（如 `-DFEATURE_X`）。
- 文件可能不存在，此时 skill 照常分析，不中断、不询问用户。

## 判定规则（两个 skill 共用）

| 场景 | 处理 |
|------|------|
| macro.json 不存在 | 照常分析 |
| 漏洞路径受宏控制，宏在 macro.json 中且值表明代码不会被编译 | 代码不可达 |
| 漏洞路径受宏控制，宏在 macro.json 中且值表明代码会被编译 | 代码可达，继续分析 |
| 漏洞路径受宏控制，宏不在 macro.json 中 | 默认代码可达 |

**"代码不会被编译"的判断**：需结合预处理指令语义。例如 `"FEATURE": "0"` 配合 `#if FEATURE` 意味着代码不编译；`"FEATURE": null` 配合 `#ifndef FEATURE` 同理。
