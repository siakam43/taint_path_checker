# taint-tree-checker 校验完备性检查设计

日期：2026-08-19
状态：已批准

## 背景与问题

taint-tree-checker 技能（`taint-tree-checker/SKILL.md`）第五章"危险使用点与校验检查"目前只判断污点数据在危险使用前**是否存在校验**。实测中发现：污点数据确实被校验了，但校验不充分（如只查上界不查下界），或校验逻辑存在整数回绕/类型混淆导致校验可绕过，这类漏洞会被漏报。

## 目标

将技能的判定语义从"未校验"升级为"**未正确校验**"：

1. 措辞修改：`挖掘因外部污点数据未校验导致的安全漏洞` → `挖掘因外部污点数据未正确校验导致的安全漏洞`
2. 新增校验完备性检查清单，指导 AI 在"存在校验"之后继续判断"校验是否完备、是否可被绕过"
3. 漏洞判定门禁第 2 问相应升级为两步判定

## 范围

- **只改 `taint-tree-checker/SKILL.md`**。兄弟技能 taint-path-checker 有相同措辞，本次不动。
- 新增一个测试夹具场景验证优化效果。
- `.claude/skills/taint-tree-checker/SKILL.md` 是指向源文件的符号链接，无需单独修改。

## 判定门槛（核心原则）

沿用技能既有核心原则"**宁可漏报，不要误报**"：

> 发现"有校验但不完备"时，**必须论证出具体的绕过方式**（具体输入值或整数溢出路径）才可上报；论证不通的视为校验有效，不上报。

## SKILL.md 修改点

### 1. 措辞修改（2 处）

- frontmatter description（第 3 行）：`挖掘因未校验导致的安全漏洞` → `挖掘因未正确校验导致的安全漏洞`
- 第五章引言（第 213 行）：`挖掘因外部污点数据未校验导致的安全漏洞` → `挖掘因外部污点数据未正确校验导致的安全漏洞`
- 第一章角色描述（第 10 行）已是"是否经过正确校验"，不改。

### 2. 新增 5.3 校验完备性检查

5.2 校验识别清单不动（回答"有没有校验"）。新增 5.3（原 5.3 排除清单顺延为 5.4），开头写明判定原则：

> **存在校验 ≠ 校验有效。** 对每个"已校验"的污点使用点，还必须检查校验是否完备、是否可被绕过。**上报门槛：必须给出具体的绕过输入或溢出路径**，论证不通的视为校验有效（宁可漏报，不要误报）。

缺陷模式清单（三张表）：

**① 边界缺陷**

| 缺陷 | 示例 | 绕过方式 |
|------|------|----------|
| 只查上界不查下界 | `if (idx >= BUF_SIZE) return; buf[idx]` | idx 为负数（有符号）时绕过 |
| 只查下界不查上界 | `if (idx < 0) return; buf[idx]` | idx 取极大值 |
| 边界差一 | `if (idx <= BUF_SIZE)` | idx == BUF_SIZE 越界一元素 |
| 校验常量与实际不一致 | `if (len < 64)` 但缓冲区为 32 | 硬编码错误常量 |

**② 整数溢出/类型混淆绕过**

| 缺陷 | 示例 | 绕过方式 |
|------|------|----------|
| 校验表达式本身溢出 | `if (idx + off < MAX); buf[idx]` | idx+off 回绕为小值通过校验 |
| 校验后参与运算溢出 | `if (size < MAX); alloc(size * elem)` | size 合法但乘积溢出→分配过小 |
| 乘法结果校验顺序颠倒 | `total = cnt * sz; if (total < MAX)` | 溢出后 total 变小通过校验 |
| 有符号/无符号错配 | `if (len < 0) return;` 而 len 为 uint32 | 恒假，极大值不拦截 |

**③ 校验对象与时序错位**

| 缺陷 | 示例 | 绕过方式 |
|------|------|----------|
| 校验的变量 ≠ 使用的变量 | 校验 `len`，使用 `len+1` | 实际值超出校验范围 |
| 校验字段 A 但使用字段 B | 校验 `hdr->total_len`，使用 `hdr->payload_len` | B 未受约束（无交叉约束时） |
| 校验副本但使用原始值 | `safe = v; if (safe<MAX); use(v)` | v 经别名在校验后被修改 |
| 校验时机在使用之后 | 先 `buf[idx]` 后 `if (idx>=MAX)` | 校验晚于危险使用 |
| 部分校验 | 校验 `len` 不校验 `off`，使用 `buf[off+len]` | off 独立控制 |

### 3. 第六章门禁升级

第 2 问由 `未校验` 改为 `未正确校验`，分两步：

> a. **是否存在校验**：按 5.2 清单检查任何形式的校验（显式或隐式）。仔细检查隐式校验，宁可误判有校验也不要漏判。
> b. **校验是否完备**：按 5.3 清单检查是否可被绕过。**必须给出具体绕过输入或溢出路径才能判定校验无效**；论证不通的视为校验有效。

### 4. 报告模板与思维陷阱联动

- 7.4 漏洞原理字段要求追加："并说明校验不完备/被绕过的方式（具体绕过输入或溢出路径）"
- 7.3 无漏洞模板末句 `经过适当校验` → `经过正确校验`
- 9.1 思维陷阱更新两处：
  - "校验不足也是一种漏洞"行：根因说明由"校验缺失"扩展为"校验缺失或不完备"（仍是根因，不是独立漏洞，只报具体安全后果）
  - 新增一行：**"这里已经有 if 校验了，所以安全"** → 存在校验≠校验有效，按 5.3 检查是否可绕过

### test.c（1 入口 3 条链）

```c
#define BUF_SIZE 64
static uint8_t g_buf[BUF_SIZE];

void FUNC0(uint32_t idx, uint32_t off, uint32_t len)
{
    if (len == 0)      FUNC1(idx, off);   /* 链1 */
    else if (len == 1) FUNC2(idx);        /* 链2 */
    else               FUNC3(len);        /* 链3 */
}

void FUNC1(uint32_t idx, uint32_t off)    /* 案例1：整数回绕绕过 */
{
    if (idx + off >= BUF_SIZE)            /* 校验表达式本身溢出 */
        return;
    g_buf[idx] = 0xAA;                    /* idx=UINT32_MAX, off=2 → 回绕通过 → OOB */
}

void FUNC2(int32_t idx)                   /* 案例2：只查上界，负数绕过 */
{
    if (idx >= BUF_SIZE)
        return;
    g_buf[idx] = 0xBB;                    /* idx=-1 → OOB */
}

void FUNC3(uint32_t len)                  /* 案例3：对照——校验完备，不应报 */
{
    if (len > BUF_SIZE)
        return;
    g_buf[len % BUF_SIZE] = 0xCC;         /* 值域被完整约束 */
}
```

- 案例 1、2 各产生一个漏洞（OOB Write），预期报告的漏洞原理须写明绕过方式（回绕输入 / 负索引）
- 案例 3 为完备校验对照：确保严格门槛生效、不误报
- 预期报告 `bypass01_result.md` 按 7.4 模板撰写，漏洞 ID 按 `file:func:line` 实际计算后填入
